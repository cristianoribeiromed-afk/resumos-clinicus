📊 Distribuição de Frequências — Conceito

🟢 Distribuição de Frequências: o arranjo dos dados em classes ou categorias, mostrando pra cada uma delas a frequência correspondente. Também chamada de "tabela de frequências".

🔢 Distribuição de Frequências — Variável Discreta

🟢 Definição: representação tabular de um conjunto de valores, onde a 1ª coluna traz os valores distintos da série em ordem crescente, e a 2ª coluna traz as frequências correspondentes.
🔴 Observação importante: esse tipo de distribuição (valor por valor) só deve ser usado se o número de elementos DISTINTOS da série for PEQUENO.
Exemplo: Acidentes por dia numa rota (20 dias)

📦 Agrupamento de Dados em Intervalos de Classes

🟢 Dados em Bruto: dados coletados que ainda NÃO foram organizados.
🟢 Ordenação: os dados numéricos em bruto dispostos em ordem crescente ou decrescente de magnitude.
🟢 Rango (Amplitude): a diferença entre o número MAIOR e o número MENOR dos dados.
Exemplo
Se a altura maior entre 100 estudantes é 185cm e a menor é 160cm: Rango = 185-160 = 25

📐 As 3 Regras Gerais de Agrupamento

PassoO que fazer
1ºDeterminar o Rango (R): valor máximo - valor mínimo
2ºDeterminar o número de classes (K), pela fórmula de Sturges: K = 1 + 3,322 × log(n), onde n = número total de dados
3ºDeterminar a amplitude de cada classe (C), pela fórmula: C = R / K
🧠 Mnemônico: "RKC" — Rango primeiro, depois K (número de classes), depois C (tamanho de cada classe).
📌 A fórmula de Sturges (K = 1+3,322×log n) é a mais cobrada em prova — decore-a exatamente.

📏 Exemplo Completo Resolvido — Alturas de 45 Estudantes

💭 Enunciado: alturas (em polegadas) de 45 estudantes do sexo feminino de uma universidade. Elaborar uma distribuição de frequências.
Passo 1 — Rango
Maior valor = 74. Menor valor = 56. R = 74 - 56 = 18
Passo 2 — Número de Classes (K)
K = 1 + 3,322 × log(45) = 1 + 3,322 × 1,653 ≈ 1 + 5,49 ≈ 7 classes (arredondado)
Passo 3 — Amplitude de Classe (C)
C = R / K = 18 / 7 ≈ 3 (arredondado pra cima, garantindo cobertura de todos os dados)

💪 Fixação rápida

✅ O que você deve lembrar
Distribuição de Frequências = arranjo dos dados em classes, mostrando a frequência de cada uma. Dados em Bruto = não organizados. Rango(R) = maior-menor. K(nº classes) = 1+3,322×log(n). C(amplitude) = R/K. Sempre verificar que soma das frequências = total de dados.
⚠️ Erro comum
Esquecer a ordem correta dos passos (primeiro R, depois K, depois C). Trocar a fórmula de K (Sturges) com a de C. Esquecer de verificar que a soma final das frequências bate com o total de dados.
⚡ Questão rápida
Por que faz sentido agrupar dados em CLASSES/intervalos (em vez de listar cada valor individual), quando estamos lidando com uma variável contínua como altura, que tem muitos valores distintos possíveis?
Essa prática de agrupamento em classes faz sentido quando você considera o problema prático que surgiria se tentássemos simplesmente listar cada valor individual distinto, como fizemos com a variável discreta do exemplo dos acidentes (que tinha poucos valores possíveis: 0,1,2,3,4). Com uma variável CONTÍNUA como altura, medida com precisão de polegadas inteiras entre 56 e 74, existem potencialmente até 19 valores distintos diferentes (56,57,58...74) que poderiam aparecer nos dados. Se tentássemos fazer uma tabela de frequência simples (valor por valor, como fizemos com os acidentes) para 45 estudantes distribuídos entre até 19 valores distintos possíveis, provavelmente teríamos MUITAS linhas na tabela com frequências muito baixas (às vezes 0, 1 ou 2 estudantes por valor específico) — isso tornaria a tabela longa, difícil de visualizar de forma útil, e não revelaria claramente o PADRÃO geral de distribuição dos dados (onde a maioria das alturas se concentra, por exemplo). Ao invés disso, agrupar os dados em classes mais amplas (cada uma cobrindo um intervalo de 3 valores, no nosso exemplo) consolida esses dados dispersos em um número muito menor de categorias (apenas 7 classes), tornando muito mais fácil visualizar e comunicar o padrão geral da distribuição — por exemplo, ficando imediatamente claro que a classe '65 a 67' concentra a maior frequência (20 de 45 estudantes, quase metade da amostra), uma informação que ficaria diluída e menos aparente numa tabela com 19 linhas individuais de baixa frequência cada. Esse é o valor fundamental do agrupamento em classes: trocar uma precisão granular excessiva (e menos útil visualmente) por uma visão mais clara e interpretável do padrão geral dos dados, aceitando uma pequena perda de detalhe individual em troca de clareza analítica.
🧠 Autoexplicação
Por que faz sentido que a fórmula do número de classes (K) use uma função LOGARÍTMICA do tamanho da amostra (n), ao invés de, por exemplo, uma relação linear simples (como K = n/10)?
Essa escolha de usar uma função logarítmica (a fórmula de Sturges: K = 1 + 3,322×log(n)) reflete um princípio importante sobre como o número IDEAL de classes deveria se comportar conforme o tamanho da amostra aumenta. Se usássemos uma relação LINEAR simples (como K = n/10, por exemplo), o número de classes cresceria proporcionalmente e SEM LIMITE conforme n aumenta — para uma amostra de 1.000 elementos, teríamos 100 classes; para 10.000 elementos, teríamos 1.000 classes. Isso rapidamente se tornaria impraticável e contraproducente: com centenas ou milhares de classes, voltaríamos exatamente ao problema que o agrupamento em classes deveria RESOLVER (uma tabela longa demais, com frequências baixas e difícil de visualizar de forma útil e interpretável). A função logarítmica, por sua natureza matemática, cresce muito mais LENTAMENTE conforme n aumenta — por exemplo, log(45)≈1,65, mas log(450)≈2,65 (apenas 1 unidade a mais, mesmo com n sendo 10 vezes maior), e log(4.500)≈3,65. Isso significa que, mesmo quando o tamanho da amostra aumenta drasticamente (multiplicado por 10 ou 100), o número de classes recomendado pela fórmula de Sturges aumenta apenas MODERADAMENTE, mantendo o número de classes numa faixa gerenciável e útil (tipicamente entre 5 e 20 classes na prática, mesmo para amostras bem grandes) — refletindo o princípio estatístico de que, mesmo com muito mais dados disponíveis, ainda queremos uma tabela de distribuição de frequências que seja visualmente interpretável e útil pra análise humana, não uma tabela que cresce sem controle proporcionalmente ao volume brute de dados coletados. Esse comportamento logarítmico equilibra 2 necessidades opostas: capturar informação suficiente sobre a distribuição dos dados (mais classes = mais detalhe) versus manter a tabela compreensível e útil (menos classes = mais clareza visual), sendo o crescimento logarítmico um meio-termo matematicamente elegante entre essas 2 necessidades conflitantes.

⚠️ Onde todo mundo escorrega

  • Confundir a ordem dos passos — sempre R primeiro, depois K, depois C
  • Trocar as fórmulas de K (Sturges: 1+3,322×log n) com a de C (R/K)
  • Esquecer de verificar que a soma final das frequências bate com o total de dados
  • Usar distribuição valor-por-valor quando o número de valores distintos é muito grande (deveria agrupar em classes)

📚 Se você só puder lembrar de 6 coisas

  1. Distribuição de Frequências = arranjo dos dados em classes, com a frequência de cada uma
  2. Dados em Bruto = ainda não organizados
  3. Rango (R) = valor maior - valor menor
  4. K (número de classes) = 1 + 3,322 × log(n)
  5. C (amplitude de classe) = R / K
  6. Sempre verificar: soma das frequências = total de dados (n)
